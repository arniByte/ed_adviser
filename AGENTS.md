# Черновик — правила для агентов

Эта ветка (`agents`) — служебная. В `main` её содержимое не попадает: организаторам хакатона нужны только продукт, документация и материалы сдачи. Здесь живут правила работы, журнал передачи, заметки о деплое и инструменты для презентации и ролика.

## Проект за минуту

AI-тренажёр для абитуриента и стажёра. Кейс «Цифровое наставничество и AI-менторство», Софтлайн Решения, категория Lead (этапы 1–4). Сдача — до 14 ноября 2026 включительно.

- Два режима: справка (вопрос → ответ по базе знаний со сносками и пруфами) и тренажёр (кейс → ответ текстом или голосом → разбор «Это верно / Что улучшить / Удачный пример» → оценка → вторая попытка → итог сессии).
- Память в `localStorage` (`chernovik:memory:v1`): незакрытые ошибки и баллы по зонам; следующая сессия начинается с контрольного вопроса.
- База знаний: `knowledge/` — 3 сценария, 60 карточек, 21 кейс, 20 типовых ошибок. Только открытые источники.
- Пруф-система: цитата со страницы источника или DOI в Crossref → SHA-256 канонического JSON карточки → дерево Меркла. `public/proofs.json`, проверка в браузере (`src/lib/proofs.ts`) и в CI (`npm run proofs:check`).

## Стек и устройство

- Vite + React 19 + TypeScript, без UI-библиотек. Шрифт Inter Variable (`@fontsource-variable/inter/opsz.css`).
- `api/` — функции Vercel (Node runtime, `export default { fetch }`). Импорты на сервере — с расширением `.js`, JSON — с `with { type: 'json' }`.
- `server/` — промпты (`prompts.ts`), сборка запроса к модели (`mentor.ts`), OpenRouter (`openrouter.ts`), защита (`guard.ts`: проверка Origin, 40 запросов за 5 минут с IP).
- `core/` — общая логика без React: типы, поиск BM25 со стеммером, протокол ответа, память, пруфы. Покрыта тестами.
- `src/` — интерфейс: `components/` (TopBar с вкладками, AsciiMark, Aura, AuraMark, RichText, Sources, ProofSheet, Composer, Orb), `features/` (home, ask, train, progress, library, proofs, report), `lib/`.
- Модель наставника: `anthropic/claude-haiku-5.5`, `reasoning: { enabled: false }`, `provider: { sort: 'latency' }`; запасная и распознавание речи — `google/gemini-3.1-flash-lite`.
- Поток ответа: NDJSON-события `cards`, `text`, `error`. Разделы ответа модели помечаются `@@right`, `@@improve`, `@@example`, `@@meta`, `@@followups`, `@@summary`, `@@plan`; ссылки на карточки — `[job-star]`.

## Проверки перед каждым коммитом

```bash
npx prettier --check .
npm run typecheck
npm test
npm run check:knowledge
npm run proofs:check
npm run build
```

То же самое запускает CI (`.github/workflows/ci.yml`). Если правились карточки базы — `npm run proofs -- --fetch --stale`, затем `npm run docs:knowledge`.

Для интерфейса — ещё и глазами: dev-сервер (`npm run dev`, порт 5173) и скриншоты Playwright на 390×844 и 1280×860. Проверять: нет ошибок в консоли, ничего не обрезано и не наезжает, анимации не оставляют `transform` на `.page` (иначе ломается `position: fixed`; поэтому у анимаций `backwards`, а оверлеи рендерятся порталом в `body`).

## Правила репозитория

- Коммиты пишутся как человек: короткий заголовок в повелительном наклонении на английском, при необходимости — абзац «зачем». **Никаких** строк `Co-Authored-By`, упоминаний ИИ-ассистентов, названий моделей и ссылок на сессии — ни в коммитах, ни в PR, ни в коде.
- В `main` — только то, что нужно читателю проекта: код, база знаний, README, `docs/architecture.md`, `docs/knowledge-base.md`, презентация и видео. Инструкции по деплою, заметки агентов и служебные скрипты — здесь, в ветке `agents`.
- Работа — в своей ветке от `main`, затем PR и слияние после зелёного CI. Не переписывать чужую историю, не отключать тесты ради зелёного CI.
- Никаких сгенерированных «на всякий случай» файлов, закомментированного кода, TODO без причины, `console.log`.
- Секреты не коммитятся. Ключ OpenRouter задаётся переменной окружения `OPENROUTER_API_KEY`.

## Стиль кода и текста

- Комментарии и тексты интерфейса — по-русски, коротко, объясняют «почему», а не «что».
- Интерфейс обращается к пользователю на «ты». Без канцелярита и без внутреннего жаргона («карточка», «метка», id) в ответах наставника.
- Числительные склоняются через `src/lib/plural.ts`.
- Контраст текста — не ниже WCAG AA: `--ink-soft` и `--ink-faint` уже подобраны.

## Дизайн-система

- Минимализм, аэрография и стекло. Кнопки: `.btn`, `.btn--primary`, `.btn--glass`, `.btn--small`, `.btn--icon`; подложки: `.surface` (без размытия) и `.glass` (настоящий `backdrop-filter`, только для плавающих элементов).
- Навигация — капсула вкладок в шапке (`TopBar.tsx`): «Тренажёр, Справка, Прогресс, База», подложка едет пружиной, страница въезжает со стороны вкладки (`html[data-dir]`).
- Графика — `Aura` (тепловой градиент 48×48 на холсте, палитры thermal / pastel / mint / dusk / ink) и `AsciiMark` (круг из букв «черновик» с каомодзи). Цвета сценариев: поступление — pastel, первая работа — thermal, первый месяц — mint (`SCENARIO_PALETTE`).
- Текст ответов проявляется по словам из размытия (`RichText reveal` + `useSmoothText`). Сноска-цифра открывает шторку пруфа.
- Производительность: холсты засыпают вне экрана и на скрытой вкладке, редкие экраны грузятся лениво, `prefers-reduced-motion` уважается.

## Журнал передачи

После каждой сессии работы допиши запись в начало `HANDOFF.md` в этой ветке: дата, ветка и коммиты, что сделано, что проверено, что осталось и на что обратить внимание. Так следующий агент начинает с того места, где ты остановился.

```bash
git fetch origin agents
git worktree add ../agents origin/agents -B agents
# правка ../agents/HANDOFF.md
git -C ../agents commit -am "Log <что сделано>" && git -C ../agents push origin agents
```
